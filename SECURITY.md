# Security policy

## Supported version

The current production deployment and the latest commit on the default branch are supported. Older versions are not supported after a replacement production deployment succeeds.

## Reporting a vulnerability

Report vulnerabilities privately through the repository's GitHub Security Advisory interface. Do not include secrets, personal information or live customer proposal data in a public issue.

Include the affected route or component, reproducible steps, expected impact and any suggested mitigation. The operator will acknowledge a complete report within two business days, triage severity within five business days and provide a remediation target after validation.

Critical issues affecting authentication, tenant isolation, recipient-token confidentiality, pricing integrity or acceptance evidence are treated as emergency changes. They require an immediate containment decision, an auditable release and post-incident review.

## Disclosure

Coordinate public disclosure with the operator after a fix is available and affected customers have been notified where required. Good-faith research that avoids privacy violations, service disruption and data modification is welcomed.
