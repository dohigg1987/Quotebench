# Cloudflare + Neon production runbook

GitHub `main` is the sovereign source. Every deployment checks out a full commit SHA, rebuilds deterministically, records SHA-256 digests, creates a GitHub provenance attestation and uploads a version to the target Cloudflare Worker. Because each environment is a separate Worker, this is a reproducible build from one pinned commit—not a claim that one unchanged container image is promoted between environments.

## Environment topology

`dev`, `test`, `preprod` and `production` are separate GitHub Environments, Workers, Neon branches, Hyperdrive configurations, R2 buckets and PDF queues. Require reviewers on `preprod` and `production`; restrict production to `main`. Configure each GitHub Environment with:

- secrets: `CLOUDFLARE_API_TOKEN`, `CLOUDFLARE_ACCOUNT_ID`, `CLOUDFLARE_HYPERDRIVE_ID`, `NEON_AUTH_BASE_URL`, `NEON_AUTH_COOKIE_SECRET`, `OPERATOR_EMAIL_SHA256`
- optional provider secrets: transactional email and Stripe values accepted by `scripts/write-cloudflare-secrets.mjs`
- variable: `PUBLIC_SITE_URL`, an HTTPS origin for that environment

Create the R2 bucket, PDF queue, dead-letter queue and Hyperdrive configuration named in `deployment/environments.json` before the first deployment. Hyperdrive should point at the matching Neon branch's pooled connection string. Never commit the connection string.

## Authentication

QuoteBench uses Neon Auth email/password sessions via the same-origin `/api/auth/*` proxy. Configure each Neon Auth instance with the matching `PUBLIC_SITE_URL` as an allowed origin. Use a unique 32+ character cookie secret in each environment. Platform administration remains independently protected by `OPERATOR_EMAIL_SHA256`; customer accounts cannot see or use operator APIs unless their email digest is allowlisted.

## Promotion and rollback

Run **Promote QuoteBench** with a full commit SHA. GitHub approval gates pause pre-production and production. After health and auth smoke tests pass, production receives an annotated `production-gold-*` tag so a last-known-good source set remains recoverable.

Rollback code by redeploying the previous Cloudflare Worker version at 100% and record the incident. Database changes must be backward compatible before promotion. Neon branch restore/PITR is the data rollback mechanism; never assume a Worker rollback reverses data.

PDFs are generated by a Cloudflare Queue consumer, outside the HTTP request path. Failed jobs retry with backoff and move to the environment's dead-letter queue after the configured limit.
